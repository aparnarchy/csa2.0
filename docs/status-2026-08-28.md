# CSA 2.0 — Build Status & Feature Spec
**As of 28 August 2026**

This is a snapshot of what's actually built and working today, as distinct from
`docs/context.md` (original product spec) and `docs/build-plan.md` (build order) —
some decisions below have since overridden or refined those documents. Where that's
happened, it's called out explicitly.

---

## 1. Stack (locked)

- **Next.js 15** (App Router) + TypeScript, mobile-first PWA
- **Cloudflare Pages + Workers + D1**, deployed via **Wrangler**, git-integrated
  auto-deploy on push to `main` (production: `csa2.pages.dev` — use `/login`, the
  bare root has a known cosmetic redirect bug, see §8)
- **Auth**: `better-auth` (email + password, open signup, no OAuth). Custom PBKDF2
  password hasher — better-auth's default `scrypt` was 503-ing on the Workers
  free-tier CPU limit.
- **AI**: Groq (`llama-3.3-70b-versatile`) via plain fetch — not Gemini/Claude.
  `GROQ_API_KEY` set as a Cloudflare Pages secret + in local `.dev.vars`.
- **Styling**: Tailwind v4. Design tokens: brand purple `#7C6FFF`, Satoshi
  (display) + Inter (body) fonts, `good`/`warn`/`bad` semantic score colours.
- **Real-time**: polling (no websockets) — this is the pilot-phase decision.

## 2. Roles & the login model

Four roles, stored as a `role[]` array per person (a real person can hold more
than one at once):

| Role | Can see |
|---|---|
| `employee` | Their own check-ins, own Analysis dashboard, own Career History, own Inbox |
| `manager` | Their team's aggregates only — **never** an individual's score or identity — plus the Action Inbox (feedback loop) |
| `ceo_hr` | Org / department / team rollups, manager leaderboard, org-wide Insights |
| `admin` | Question bank, org structure, invites, Wisdom content CMS |

`/dashboard` redirects to whichever role is highest-priority for that person, but
each role-scoped route (`/dashboard/employee`, `/dashboard/manager`, etc.) is
independently reachable by anyone holding that role — so a dual-role account
(e.g. a manager who is also rated as an employee) genuinely sees both views, and
can switch between them from Profile ("Switch to manager view").

**Privacy is enforced server-side**, not in the UI, on every query:
- A manager query never returns an individual's score or identity — aggregates only.
- Anonymisation floor: **≥3 responses** AND **≥3 distinct reportees** before a
  team/scope will render anything.
- A manager's logged action is invisible to employees until **4 weeks**
  (`visibleToEmployeesAt = submittedAt + 28 days`) after submission.
- Journal entries are strictly typed: `follow_up` (employee's own reflection,
  author-only) vs `coaching` (manager's private note — never shown to the employee).
- Career History is **employee-only**: as of today, anyone holding the `manager`
  role no longer sees Career History anywhere, even on their own Profile, and
  direct navigation to `/career` redirects them back to Profile. (This overrides
  `context.md`'s original spec, which had Career History in one shared profile
  regardless of role — owner call, 2026-08-28.)

## 3. The four pillars & the check-in question bank

Fixed pillar set (`lib/pillars.ts`), same order everywhere:

1. **Meaningful Work**
2. **Growth**
3. **Culture**
4. **Compensation**

**Check-in question bank** (`questions` table) was swapped from 10 placeholder
questions to the owner's real 15-question set on 2026-08-24 (`docs/checkin-questions.csv`,
importable via Admin → Question Bank's CSV upload). Each question has a fixed
A/B/C answer scale scored **4 (worst) / 7 (mid) / 10 (best)**. The old 10 questions
were **deactivated, not deleted**, to preserve production check-in history
(thousands of existing check-ins and pending assignments point at them).

A question's `isActive` flag governs only **future assignment** (`lib/scheduler.ts`
never hands out a deactivated question again). It must never gate whether an
*existing* answer can be saved or read back — a bug class fixed today, see §8.

Two questions are delivered per person per week (`lib/scheduler.ts`,
self-healing on read, no cron dependency for correctness — a cron endpoint
(`/api/cron/weekly`) exists to roll every active employee forward on schedule).

## 4. Screen-by-screen status

### Auth & onboarding
`(auth)/login`, `(auth)/signup`, `(auth)/reset-password`, `(app)/onboarding` — real,
D1-backed. Signup is open to any email (personal or work), no invite required.

### Employee
- **Dashboard / Analysis** (`dashboard/employee`) — real scores from `lib/scores.ts`
  (`getEmployeeScores`, `getPillarDetail`), own-data only. Benchmarks/percentiles
  are still a sample derivation (no real cross-company benchmark source yet).
- **Check-in flow** (`/check-in`) — a **transient, push-triggered screen**, not a
  navigable destination (no nav entry, no back button into it). Order: this
  week's fresh questions (full-screen, auto-advance) → catch-up carousel
  (visually distinct, for earlier unanswered weeks) → return check-in ("did you
  act on your last recommendation?", only if one's open, with a 2-day cooldown
  to prevent looping) → done → dashboard.
- **"Find the Root"** (root-cause section on a low score) — currently a fully
  **deterministic** stand-in (`lib/rca.ts` + `lib/rca-knowledge.ts` + `lib/voice.ts`):
  weakest pillar → weakest question → a fixed 4-entry knowledge-base lookup. It is
  explicitly documented as the Phase-5 AI's placeholder. **Not yet doing what the
  owner wants**: reasoning over real career-history patterns, current check-in
  dips, and journaling-prompt answers to infer a genuinely plausible root cause.
  A phase-wise build plan for this exists (presented 2026-08-27, Phase 0 owner
  decisions still pending approval).
- **Career History** (`/career`) — real, `lib/career.ts`. Two data sources with
  different completeness: the one-off career questionnaire yields only overall +
  4 pillar scores + per-question score (no delta/percentile/breakdown/trend —
  a single respondent can't produce those); a company built up via weeks of
  dashboard use yields the full field set. The UI renders each block only when
  its data exists — never a fake zero. **Now hidden entirely for manager-role
  accounts** (see §2).

### Manager
- **Team dashboard** (`dashboard/manager`) — real, `lib/team.ts`
  (`getTeamAggregate`, `getTeamPillarDetail`). Enforces own-team-only, employment-scoped
  reportees, the ≥3/≥3 anonymisation floor. Aggregates only, never an individual.
- **Action Inbox** (`dashboard/manager/inbox`) — the feedback-action loop, real,
  `lib/feedback.ts`. Open items = any team pillar scoring below the trigger
  threshold with its weakest question identified; manager logs "yes, I took an
  action" (→ resolved, visible to eligible employees after the 4-week delay,
  logs a private `coaching` journal note) or "not yet" (→ stays in-progress).
- **AI insight** — live on this dashboard (see §5).

### CEO/HR
Three tabs (`dashboard/ceo-hr`): **Dashboard** (org score + department panels →
drill-down), **department detail** (score/pillars/AI insight/action-impact/trend,
same floor rules), **Insights** (dept bar chart, top/bottom managers, ranked
manager list → per-manager team detail, scoped pillar ranking). All real,
`lib/ceo.ts`. (The old separate "reviewing-manager" role was removed entirely on
2026-08-06 — its job folded into this Insights tab; `lib/reviewing.ts` still
exists but now serves CEO/HR only.)

### Admin
Hub (`dashboard/admin`) with four real, D1-backed sub-screens: **Question Bank**
(CRUD + CSV import/export), **Org Structure** (departments/teams), **Invites**
(CSV upload → pending invite rows — narrow: creates invites, not full employee
records), **Wisdom content CMS** (structure exists; no real content loaded yet,
see §7).

### Shared
- **Profile** — real, `lib/profile.ts`: streak/activity, badges, appearance
  (Professional/Play mode + Spiderman/Batman persona), notification prefs
  (local-only, not yet persisted), manager-view switch if dual-role.
- **Inbox** — unanswered check-ins, own reflections, feedback-action responses.
- **Wisdom** — Beginner/Advanced/Expert levels + modules. **Badges section
  removed from the UI today** (owner call) — earned-badge tracking still exists
  in the data model, just not surfaced here anymore. Content itself is still
  hardcoded placeholder copy (`MODULE_COPY` in `lib/data.ts`) — the owner's real
  videos/articles haven't been loaded yet.

## 5. AI insight generation — confirmed genuinely live

`lib/ai.ts`, server-only: builds an **aggregates-only** prompt (no individual
data ever reaches the model — consistent with the manager-privacy rule), calls
Groq, caches the result in the `aiInsights` D1 table keyed by scope + time window
+ a fingerprint of the underlying scores (so it only regenerates when the
numbers actually change). Wired into the manager dashboard, every CEO/HR scope,
and career-company comparisons. Any failure (timeout, bad key, rate limit) falls
back to static copy rather than showing an error. Verified working in production
by finding real, non-templated cached text in the `aiInsights` table.

This is a **separate system** from "Find the Root" (§4) — the AI insight boxes
are real AI already; the root-cause section is not yet.

## 8. Fixed today (2026-08-28)

A single root cause, found in four places: **`isActive` on a question was
gating more than future assignment.** After deactivating the old 10 check-in
questions (§3), it turned out:

- `submitCheckIn` refused to save an answer for any question that wasn't
  currently active — so answering an old pending catch-up question silently
  failed, and the assignment never left "pending," looping the catch-up screen
  forever. **This is why check-in testing got stuck partway through.**
- The employee's own per-question dashboard breakdown, and the manager/CEO
  per-team and per-scope breakdowns, all built their question list from
  active-only questions — so any historical answer tied to a now-inactive
  question silently vanished from those lists.
- The manager Action Inbox's "weakest question" trigger lookup had the same
  restriction, which meant **no team anywhere could show an Open item** (since
  none of the new questions had check-in history yet) and blanked the
  trigger-question text on already-resolved actions.

All four fixed to read across every question ever asked, not just active ones.
Deployed and confirmed working live (India Sales Team's open items now surface
correctly; a real manager→employee action was submitted, backdated past its
4-week delay for testing, and confirmed visible to the employee).

Also shipped today: Wisdom Badges section removed from the UI; Career History
hidden for any account holding the manager role (§2); one demo account
(`d-marketing-mgr@csademo.test`) found with zero role rows at all — fixed by
granting it `employee` + `manager` to match its sibling department-manager accounts.
